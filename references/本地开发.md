← [[README]] · [项目根 README](../README.md) | 测试详情 → [[references/agent-testing]] · [agent-testing.md](agent-testing.md)

本项目的增量开发以 **`terminology-agent/`** 为主。Java 后端 [`translationtoolservice/`](../translationtoolservice) 一般只通过 Docker 运行；MySQL / Redis 也一律放 Docker，不必本机安装。

## 0. 快速开始

### 0.0 一键本地全栈（推荐）

```powershell
cd F:\Documents\Repertory\Sieyuan\translationtool

pnpm setup
# 编辑 terminology-agent/.env 填入 LLM_API_KEY

pnpm install
pnpm -C translationtoolservice install
pnpm -C terminology-agent install

pnpm dev              # 全本地 UI+Java+Agent，WT 分 pane
# → http://localhost:18000
```

**浏览器统一入口：http://localhost:18000**（本地 webpack 热更新与 Docker nginx 同端口，由命令决定哪一层在本地跑）。

| 根目录命令 | **本地** | **Docker** | 说明 |
|------------|----------|------------|------|
| **`pnpm dev`** | UI + Java + Agent | infra | 全栈本地 |
| **`pnpm dev:ui`** | UI | infra + Java + Agent | 只改前端 |
| **`pnpm dev:java`** | Java | infra + Agent + UI | 只改 Java |
| **`pnpm dev:agent`** | Agent | infra + Java + UI | 只改 Agent |
| **`pnpm dev:ui-java`** | UI + Java | infra + Agent | 改前端 + Java |
| **`pnpm dev:ui-agent`** | UI + Agent | infra + Java | 改前端 + Agent |
| **`pnpm dev:java-agent`** | Java + Agent | infra + UI | 改 Java + Agent |
| **`pnpm infra`** | — | mysql + redis | 仅基础设施 |

每条命令会先执行 `scripts/dev/prepare-stack.js`（互斥停本地/Docker、健康检查、`docker compose up`），再在 **Windows Terminal** 分 pane 起本地进程（需安装 `wt.exe`）。

环境变量文件：

| 文件 | 用途 |
|------|------|
| `translationtoolservice/.env.local` | 本机 Java **18001** |
| `terminology-agent/.env` | Agent 数据库 / LLM 密钥 |

### 0.1 整体验收（全 Docker，不改代码）

```powershell
cd F:\Documents\Repertory\Sieyuan\translationtool
docker compose up -d
# → http://localhost:18000  登录 admin / admin123
```

### 0.2 只改前端（等价于 `pnpm dev:ui`）

```powershell
pnpm dev:ui
# prepare 起 Docker Java/Agent/infra + 本地 webpack :18000
# → http://localhost:18000
```

启动时 webpack pane 会打印：`[dev-proxy] mode=serve api=http://localhost:18001 agent=http://localhost:18002`

### 0.3 translation/ 内 proxy 四档（根命令自动注入）

| proxy mode | Java | Agent | 根命令示例 |
|------------|------|-------|------------|
| **`serve`** / **`dev`** / **`dockerJava`** / **`dockerPy`** | **:18001** | **:18002** | proxy 目标相同；差异由 prepare 决定谁在本地/Docker |

`translation/package.json` 仍保留 `serve` / `dev` / `dev:dockerJava` / `dev:dockerPy` 供根脚本与手动调试调用。

## 2. MySQL / Redis：放 Docker 就够

**结论：对日常开发几乎没区别，一律放 Docker，不必本机安装。**

| 维度 | Docker 跑 MySQL/Redis | 本机安装 |
|------|----------------------|----------|
| 连接方式 | 宿主机 `127.0.0.1:3306` / `6379` | 同样 |
| Agent `.env` | `MYSQL_HOST=127.0.0.1`（默认值） | 相同 |
| 数据持久化 | `docker volume mysql-data` | 本机数据目录 |
| 初始化 | 首次起容器自动跑 `db/init/` | 需手动建库导入 |

### 与 Agent 的关系

- **MySQL**：Agent **需要**。读写库 **`translationtool`**（审核表、术语表等）。`.env` 里 `MYSQL_HOST=127.0.0.1` 即连 Docker 映射出来的端口。
- **Redis**：Agent **不需要**（代码中无 redis 引用）。仅 Java 后端使用；起 `translationtoolservice` 时 docker compose 会顺带起 redis，Agent 开发者无需配置。

### Agent 场景最小 Docker 集合

| 目的 | 起的容器 |
|------|----------|
| 只测 Agent API / OpenAPI | `mysql`（+ `docker stop terminology-agent`） |
| 登录 + 看现有页面（非术语学习 Agent 联调） | `mysql` + `redis` + `translationtoolservice` + `translation-ui` |
| 术语学习 UI + 本地 Agent | `mysql` + `redis` + `translationtoolservice`（见场景 B） |

## 6. 前端页面改动要点（非主路径）

仅在做术语学习 UI 或新菜单页时需要：

1. **菜单**：`db/opt/` 增量 SQL → 库 **`translationtool`**（不是 `SymbolMaker`）
2. **路由**：[`asyncRouter.js`](../translation/src/router/asyncRouter.js) 动态加载 `views/` 下组件
3. **API 模块**：`src/http/api/` 下新增，路径走 `/agent/*`
4. **侧边栏图标**：DB `icon` 须与 [`layout.vue`](../translation/src/views/layout/layout.vue) 的 `menuIcon` 键一致（如 `Config`，不是 `configIcon`）
5. 改菜单后 **重新登录**（菜单缓存在 sessionStorage）

## 9. 常见问题

### Q: Agent 本地跑，18000 术语学习页接口失败？

18000 的 Docker nginx 默认代理到**容器** Agent。联调本地 Agent 请用 **`pnpm dev:ui-agent`**（本地 webpack + proxy）或直连 **18002/docs**。

### Q: 启动 uvicorn 报 18002 端口占用？

```powershell
docker stop terminology-agent
```

### Q: 改了 Navicat 菜单，前端没变化？

1. 确认库是 **`translationtool`**，不是 `SymbolMaker`
2. Docker 后端连的是**容器 MySQL**，不是远程 196.125（除非改了后端配置）
3. 重新登录清 menu 缓存

### Q: 术语学习有文字无图标？

`t_menu` 的 `icon` / `active_icon` 须为 `Config` / `ConfigActive`（不能 NULL 或 `configIcon`）。

### Q: 18000 登录 ECONNREFUSED / proxy 到 18001 失败？

**端口与 dev 命令必须一致**：

| 本机 Java 端口 | Agent 端口 | 根目录命令 / proxy |
|----------------|------------|-------------------|
| Docker 18001 | Docker 18002 | `pnpm dev:ui`（proxy `serve`） |
| 18001 | 18002 | `pnpm dev`（proxy `dev`） |

webpack 会把 API 代理到 **18001**（`dev` mode）。若 Java 开在 **18001** 而 proxy 指向 18001，会出现 `ECONNREFUSED`。

**修法**：在仓库根目录用匹配的 `pnpm dev:*`，或手动：

```powershell
pnpm -C translationtoolservice dev   # Java :18001
pnpm -C terminology-agent dev        # Agent :18002
pnpm -C translation dev              # webpack proxy mode=dev
```

### Q: 18000 报错但堆栈含 `/app/app.jar`？

前端模式与真实后端不一致：请求仍打到 **Docker Java**。核对：

1. 终端 `[dev-proxy]` 打印的 mode 与端口
2. `pnpm dev:dockerPy` 时 Java 应在 **18001**，不是 Docker 18001
3. `netstat -ano | findstr :18001` 与 `docker ps` 对照

### Q: 18000 登录失败 / 404？

1. `docker compose ps` 或本机 Java 是否在对应端口监听
2. `serverURL` 保持 `''`
3. 确认 webpack proxy mode 与当前栈一致（见 §0.3）；根目录 `pnpm dev:*` 会自动 prepare

### Q: `docker exec ... WHERE menu_name='术语学习'` 查不到？

PowerShell 中文乱码，改用 `WHERE id='16'` 或 `WHERE name='terminologyAgent'`。

### Q: 18000 上是 webpack 还是 Docker nginx？

| 地址 | 用途 |
|------|------|
| http://localhost:18000 | **webpack**（`pnpm dev:ui*` / `pnpm dev`）— 改 UI 即时生效 |
| http://localhost:18000 | **Docker nginx**（`pnpm dev:java*`）— UI 在容器，后端可混合本地 |

## 附录：dev proxy 四档矩阵

### 端口约定

| 组件 | Docker（宿主机映射） | 本机调试 |
|------|---------------------|----------|
| Java API | 18001 | **18001** |
| Agent | 18002 | **18002** |
| 前端 dev server | — | 18000 |
| 前端 Docker nginx | 18000 | — |

Docker 与本机后端**可同时运行**，靠不同端口区分；前端脚本决定 proxy 打哪一组。

### 四档对照

| pnpm 脚本 | 需启动的 Docker | 需启动的本机进程 | Java proxy → | Agent proxy → |
|-----------|----------------|------------------|--------------|---------------|
| `serve` | mysql, redis, translationtoolservice, terminology-agent | 无 | :18001 | :18002 |
| `dev` | mysql, redis | Java :18001, Agent :18002 | :18001 | :18002 |
| `dev:dockerJava` | mysql, redis, translationtoolservice | Agent :18002 | :18001 | :18002 |
| `dev:dockerPy` | mysql, redis, terminology-agent | Java :18001 | :18001 | :18002 |

### 后端连库（与前端脚本无关）

| 进程位置 | MySQL | Redis |
|----------|-------|-------|
| Java **容器** | `mysql:3306` | `redis:6379` |
| Java **本机** | `127.0.0.1:3306` | `127.0.0.1:6379` |
| Agent **容器** | `mysql:3306` | — |
| Agent **本机** | `127.0.0.1:3306`（`.env`） | — |

日常开发 MySQL/Redis 均在 Docker；本机进程统一连 `127.0.0.1`，不必再装本机 MySQL。

### 本机 Agent 环境变量

```env
AGENT_HOST=0.0.0.0
AGENT_PORT=18002
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=123456
MYSQL_DATABASE=translationtool
```

### 如何判断请求打到 Docker 还是本机

| 线索 | Docker Java | 本机 Java |
|------|-------------|-----------|
| 报错堆栈 | `jar:file:/app/app.jar!/...` | `target/classes` 或本地路径 |
| 监听端口 | `docker ps` 映射 18001 | `java.exe` 监听 **18001** |
| dev server 启动 log | `mode=serve` 且 api=:18001 | `mode=dev:dockerPy` 且 api=:18001 |

### 18000：webpack vs Docker UI

| 地址 | 前端 | 后端 |

### 词条管理查询报错（Communications link failure）

切换产品分类时并发请求 `getEntrySourcesByClassify` / `getWriteFileNamesByClassify`。若约 20s 超时且堆栈含 `/app/app.jar`，说明打到 **Docker Java** 且容器网络空闲断连 + Druid 连接池未校验。排查：

1. 用 `pnpm dev:ui-java` + 本机 Java :18001 验证是否为 Docker 专有问题
2. Docker 路径需 `mvn package` → `docker compose build translationtoolservice` → 重启
3. 详见 [[references/db-connection-pool]]
