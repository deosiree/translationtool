# 0012 AI 大模型应用学习驱动开发

Date: 2025-07-17

## Status

Accepted

## Context

开发者（崔雄）正在准备「大语言模型应用/算法工程师」岗位面试，需要系统学习 AI 大模型应用落地的全流程技术栈。面试策略是「全流程广度 + RAG 和长短期记忆两个深挖点」。

开发者决定将本翻译工具项目作为实战载体，通过逐步增加 AI 能力（智能助手 → RAG → 记忆系统 → Agent）来驱动学习，同时让项目本身功能更完善。

## Decision

1. **学习与项目并行**：新功能开发同时服务面试学习和项目实用两个目标
2. **云端大模型优先**：使用 DeepSeek / 千问 API，不做本地模型部署、不做训练/微调实战
3. **ChatWidget 为入口**：以全局智能助手作为首个学习成果，逐步叠加 RAG、记忆、Agent 能力
4. **训练类知识只读不写**：SFT / RLHF / LoRA 等只通过论文和博客学习原理，不做工程实战
5. **学习方案文档化**：`docs/product/learning-plan.md` 作为总路线图 SSOT；里程碑倒序写入 `docs/product/learning-log.md`

## Alternatives Considered

1. **从头做独立 Demo 项目**：环境搭建成本高，与本项目脱节，面试时缺乏「企业项目背景」说服力 — 放弃
2. **所有环节都做工程实战（含训练）**：需要 GPU 资源、数据标注、时间成本过高 — 放弃
3. **只读书不实战**：缺乏代码证据，面试难以深入 — 放弃

## Consequences

Positive:

- 面试有真实企业项目背景支撑，代码证据可展示
- 学习成果直接转化为项目功能价值（智能助手能帮用户使用翻译工具）
- 「云端大模型应用」定位精准，聚焦面试最常问的工程落地问题

Tradeoffs:

- 项目方向从纯翻译工具扩展到 AI 应用平台，需注意模块边界
- 部分学习内容（如训练）需理论补充，无法通过项目工程验证
- 学习进度依赖开发者个人时间投入

## Follow-Up

- 路线图变更时更新 `docs/product/learning-plan.md`；完成里程碑时在 `docs/product/learning-log.md` 文首追加（改 bug 不入账）
- RAG 知识库接入后，智能助手可回答项目使用问题，形成自举闭环
