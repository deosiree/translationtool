# 国际化TS/DIC文件导出及自动化编译提交流程技术方案

## 1\. 方案概述

本方案用于规范项目国际化TS、DIC翻译文件的导出更新、自动化编译、仓库提交全流程操作，实现翻译文件回填导出、自动生成编译产物、仓库配置自动更新的标准化闭环能力。方案分为**翻译文件导出流程**和**文件上传自动化流水线流程**两大模块，全程标准化、自动化，保障国际化文件迭代的准确性与高效性。

## 2\. 适用范围

适用于项目lang语言仓库下所有TS翻译源文件、DIC字典文件的翻译回填导出、产物编译、仓库更新迭代场景，支持单文件、多文件批量操作及整目录批量处理。

## 3\. 核心整体流程

用户本地获取抽取后的原始TS/DIC文件 → 通过管理工具导入文件中的词条并翻译 → 通过管理工具完成翻译自动回填并导出文件压缩包 → 按需获取单/多文件产物 → 上传TS/DIC文件触发流水线 → 流水线自动完成代码拉取、产物编译、配置更新、仓库提交，完成全流程迭代。

## 4\. 翻译文件导出操作流程

### 4\.1 文件选择规则

用户需选择本地已完成抽取的原始TS、DIC文件进行导出操作，支持**两种选择方式**：一是单独多选单个或多个TS、DIC文件；二是直接选中lang根文件夹，系统自动识别文件夹内全部TS、DIC文件，覆盖批量处理场景。

### 4\.2 翻译回填规则

用户确认选中文件并**点击导出后**，系统自动匹配对应翻译内容，批量回填至选中的原始TS、DIC文件中，生成内容完整、翻译齐全的最新版本TS、DIC文件，保证文件原有格式、路径、键值结构不变，仅更新翻译内容。

### 4\.3 文件导出交付方式

回填完成后，系统自动将所有更新后的文件打包为ZIP压缩包。支持**两种交付模式**，可根据使用场景灵活选择：模式一为直接向用户提供完整ZIP压缩包，供用户整体下载保存；模式二为解压压缩包后，向用户提供包内单个TS、DIC文件的独立下载入口，支持按需单独获取文件。

## 5\. 自动化流水线操作流程

本流程无需人工干预编译、配置修改及仓库提交操作，用户仅需完成文件提交，后续全流程由流水线自动执行。

### 5\.1 流水线触发条件

用户提交更新后的DIC、TS文件，即可触发自动化流水线任务，启动后续标准化处理流程。

### 5\.2 流水线执行步骤

1. **拉取代码仓库**：流水线自动拉取远程lang语言仓库最新代码，保障基于最新仓库内容进行迭代操作，避免版本滞后冲突。

2. **执行文件编译生成**：自动运行标准化编译脚本，对提交的TS、DIC文件进行编译处理，批量生成对应的QM、RD编译产物文件。

3. **配置文件更新**：自动识别本次新增/更新的DIC文件，将对应文件信息添加至i18n\.json配置文件的dicList列表中，完成字典配置的同步更新，保证配置与实际文件一致。

4. **自动提交仓库**：流水线将更新后的TS、DIC文件、生成的QM、RD产物文件及修改后的i18n\.json配置文件，统一提交推送至远程lang仓库，完成版本迭代归档。

## 6\. 方案落地约束与规范

1. 文件操作必须基于**本地抽取后的原始TS/DIC文件**开展导出回填操作，禁止使用非抽取原始文件操作，避免文件结构异常导致回填失败。

2. 批量选择lang文件夹操作时，系统仅识别目录内标准TS、DIC格式文件，无关文件不会参与导出及编译流程。

3. 流水线自动更新i18n\.json的dicList列表时，需保障文件信息唯一性，避免重复录入相同DIC文件配置。

4. 所有文件命名、存储路径需遵循lang仓库统一规范，保障流水线编译、配置识别、仓库提交流程正常执行。

5. 流水线执行全程保留版本记录，所有文件更新、配置修改、仓库提交均可溯源，支持异常场景版本回滚。
