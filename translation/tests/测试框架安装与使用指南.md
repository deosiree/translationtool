## 测试类型概述

### 1. 单元测试 (Unit Testing)
**定义**：测试单个函数或模块的功能是否正确

**特点**：
- 测试范围最小，速度快
- 隔离外部依赖（使用 mock）
- 验证函数输入输出

**示例**：测试 `byteLength()` 函数是否正确计算字符串字节长度

### 2. 集成测试 (Integration Testing)
**定义**：测试多个模块协同工作是否正常

**特点**：
- 测试模块间的交互
- 可能涉及数据库、API 调用
- 速度比单元测试慢

**示例**：测试 `handleAsyncRequest()` 与表单验证、API 调用的完整流程

### 3. 组件测试 (Component Testing)
**定义**：测试 Vue 组件的渲染和交互

**特点**：
- 使用 @vue/test-utils
- 测试组件 props、events、slots
- 模拟用户交互

**示例**：测试按钮组件点击后是否正确触发事件

### 4. 端到端测试 (E2E Testing)
**定义**：测试完整用户流程

**特点**：
- 在真实浏览器中运行
- 测试完整业务流程
- 速度最慢，但最接近真实场景

**工具**：Playwright、Cypress、Nightwatch

**示例**：测试用户登录 → 创建词条 → 保存的完整流程

### 5. 手工测试 (Manual Testing)
**定义**：人工操作验证功能

**特点**：
- 不需要编写代码
- 可以发现自动化测试遗漏的问题
- 适合测试 UI/UX、边界情况

## 测试框架安装步骤

### 步骤 1: 安装测试依赖

打开终端，在项目根目录执行：

```bash
# 安装 Vitest 和相关依赖
npm install -D vitest @vue/test-utils jsdom @vitest/ui

# 如果需要代码覆盖率工具
npm install -D @vitest/coverage-v8
```

**依赖说明**：
- `vitest` - 测试框架（类似 Jest，但更快）
- `@vue/test-utils` - Vue 组件测试工具
- `jsdom` - 模拟浏览器 DOM 环境
- `@vitest/ui` - 可视化测试界面
- `@vitest/coverage-v8` - 代码覆盖率工具

### 步骤 2: 创建 Vitest 配置文件

在项目根目录创建 `vitest.config.js`：

```javascript
import { defineConfig } from 'vitest/config'
import vue from '@vitejs/plugin-vue'
import { resolve } from 'path'

export default defineConfig({
  plugins: [vue()],
  test: {
    // 使用 jsdom 环境模拟浏览器
    environment: 'jsdom',
    // 启用全局 API（describe, it, expect 等）
    globals: true,
    // 测试文件匹配模式
    include: ['tests/**/*.{test,spec}.{js,mjs,cjs,ts,mts,cts,jsx,tsx}'],
    // 代码覆盖率配置
    coverage: {
      provider: 'v8',
      reporter: ['text', 'json', 'html'],
      exclude: [
        'node_modules/',
        'tests/',
        '*.config.js',
        'src/main.js',
        'src/router/**',
        'src/store/**',
      ],
      // 覆盖率阈值
      thresholds: {
        lines: 80,
        functions: 80,
        branches: 80,
        statements: 80
      }
    }
  },
  resolve: {
    alias: {
      '@': resolve(__dirname, './src')
    }
  }
})
```

### 步骤 3: 更新 package.json

在 `package.json` 的 `scripts` 中添加测试命令：

```json
{
  "scripts": {
    "test": "vitest run",
    "test:watch": "vitest",
    "test:ui": "vitest --ui",
    "test:coverage": "vitest run --coverage"
  }
}
```

**命令说明**：
- `npm test` - 运行一次测试并退出
- `npm run test:watch` - 监听模式，文件变化自动运行测试
- `npm run test:ui` - 打开可视化测试界面
- `npm run test:coverage` - 生成代码覆盖率报告

### 步骤 4: 创建测试目录结构

创建以下目录结构：

```
项目根目录/
├── tests/
│   └── unit/
│       └── utils/
│           ├── dataStructureUtils.test.js
│           ├── dateUtils.test.js
│           ├── validationUtils.test.js
│           └── ... (其他测试文件)
```

执行命令创建目录：

```bash
# Windows PowerShell
mkdir -p tests/unit/utils

# Linux/Mac
mkdir -p tests/unit/utils
```

## 编写单元测试

### 示例 1: 纯函数测试（dataStructureUtils.test.js）

```javascript
import { describe, it, expect } from 'vitest'
import { 
  filter_arr, 
  filter_arr_with_children, 
  intersection,
  getPathByKey 
} from '@/utils/dataStructureUtils'

describe('dataStructureUtils', () => {
  describe('filter_arr', () => {
    it('应该从源数组中移除指定数组中的元素', () => {
      const source = [
        { id: 1, name: 'A' },
        { id: 2, name: 'B' },
        { id: 3, name: 'C' }
      ]
      const toRemove = [{ id: 2, name: 'B' }]
      const result = filter_arr(source, toRemove)
      
      expect(result).toHaveLength(2)
      expect(result).not.toContainEqual({ id: 2, name: 'B' })
    })

    it('应该处理空数组', () => {
      const source = []
      const toRemove = [{ id: 1 }]
      const result = filter_arr(source, toRemove)
      
      expect(result).toEqual([])
    })
  })

  describe('intersection', () => {
    it('应该返回两个数组的交集', () => {
      const arr1 = [1, 2, 3, 4]
      const arr2 = [3, 4, 5, 6]
      const result = intersection(arr1, arr2)
      
      expect(result).toEqual([3, 4])
    })

    it('应该处理空数组', () => {
      expect(intersection([], [1, 2])).toEqual([1, 2])
      expect(intersection([1, 2], [])).toEqual([1, 2])
    })
  })

  describe('getPathByKey', () => {
    it('应该返回树形数据中指定节点的路径', () => {
      const treeData = [
        {
          key: '1',
          title: '根节点',
          children: [
            { key: '2', title: '子节点1' },
            {
              key: '3',
              title: '子节点2',
              children: [
                { key: '4', title: '孙节点1' }
              ]
            }
          ]
        }
      ]
      
      const path = getPathByKey(treeData, '4')
      expect(path).toEqual(['根节点', '子节点2', '孙节点1'])
    })

    it('应该返回 null 当节点不存在时', () => {
      const treeData = [{ key: '1', title: '节点' }]
      const path = getPathByKey(treeData, '999')
      expect(path).toBeNull()
    })
  })
})
```

### 示例 2: 时间函数测试（dateUtils.test.js）

```javascript
import { describe, it, expect, vi } from 'vitest'
import { getCurrentFormattedTime, getCurrentStringTime } from '@/utils/dateUtils'

describe('dateUtils', () => {
  describe('getCurrentFormattedTime', () => {
    it('应该返回正确格式的时间字符串', () => {
      const time = getCurrentFormattedTime()
      // 验证格式：YYYY-MM-DD HH:mm:ss
      expect(time).toMatch(/^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}$/)
    })

    it('应该返回当前时间', () => {
      const before = new Date()
      const time = getCurrentFormattedTime()
      const after = new Date()
      
      const timeDate = new Date(time)
      expect(timeDate.getTime()).toBeGreaterThanOrEqual(before.getTime())
      expect(timeDate.getTime()).toBeLessThanOrEqual(after.getTime())
    })
  })

  describe('getCurrentStringTime', () => {
    it('应该返回正确格式的时间字符串', () => {
      const time = getCurrentStringTime()
      // 验证格式：YYYYMMDDHHmmss（14位数字）
      expect(time).toMatch(/^\d{14}$/)
    })
  })
})
```

### 示例 3: 需要 Mock 的函数测试（validationUtils.test.js）

```javascript
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { byteLength, getMaxLength } from '@/utils/validationUtils'
import { checkSykEntryBeforeSave } from '@/http/api/glossary'

// Mock API 调用
vi.mock('@/http/api/glossary', () => ({
  checkSykEntryBeforeSave: vi.fn()
}))

describe('validationUtils', () => {
  beforeEach(() => {
    vi.clearAllMocks()
  })

  describe('byteLength', () => {
    it('应该正确计算中文字符的字节长度', () => {
      expect(byteLength('测试')).toBe(4) // 每个中文2字节
      expect(byteLength('hello')).toBe(5) // 每个英文1字节
      expect(byteLength('hello测试')).toBe(9) // 5 + 4
    })

    it('应该处理 null 和 undefined', () => {
      expect(byteLength(null)).toBe(0)
      expect(byteLength(undefined)).toBe(0)
    })

    it('应该去除首尾空格', () => {
      expect(byteLength('  test  ')).toBe(4)
    })
  })

  describe('getMaxLength', () => {
    it('应该从 classifyLimit 中获取最大长度', () => {
      const record = { classfy1: 'category1' }
      const vm = {
        classifyLimit: {
          category1: {
            foreignMaxByte: 100,
            maxByte: 50
          }
        }
      }

      expect(getMaxLength(record, vm, 'foreignMaxByte')).toBe(100)
      expect(getMaxLength(record, vm, 'maxByte')).toBe(50)
    })

    it('应该返回 record.maxLength 当没有分类时', () => {
      const record = { maxLength: 200 }
      const vm = {}

      expect(getMaxLength(record, vm)).toBe(200)
    })
  })
})
```

```javascript
    })
```

### 2. 监听模式（开发时推荐）

```bash
npm run test:watch
```

**特点**：
- 文件变化时自动运行相关测试
- 快速反馈，提高开发效率


**功能**：
- 浏览器打开测试界面
- 查看测试结果、覆盖率
- 调试失败的测试

### 4. 生成覆盖率报告

```bash

```

**输出**：
- 终端显示覆盖率摘要
- 生成 `coverage/` 目录，包含 HTML 报告

**查看 HTML 报告**：
```bash

start coverage/index.html

# Mac
open coverage/index.html

# Linux
xdg-open coverage/index.html
```

```bash

# 运行匹配模式的测试
```

```javascript
})
```

然后运行：
```bash
npx vitest --inspect-brk
```

## 测试最佳实践

### 1. 测试命名规范

```javascript
// ✅ 好的命名
describe('byteLength', () => {
  it('应该正确计算中文字符的字节长度', () => {})
  it('应该处理 null 和 undefined', () => {})
})

// ❌ 不好的命名
describe('test1', () => {
  it('test', () => {})
})
```

### 2. 测试结构（AAA 模式）

```javascript
it('测试用例', () => {
  // Arrange（准备）：设置测试数据
  const input = '测试'
  
  // Act（执行）：调用被测试的函数
  const result = byteLength(input)
  
  // Assert（断言）：验证结果
  expect(result).toBe(4)
})
```

### 3. 测试独立性

- 每个测试应该独立运行
- 不依赖其他测试的执行顺序
- 使用 `beforeEach` 和 `afterEach` 清理状态

### 4. Mock 外部依赖

```javascript
// Mock API 调用
vi.mock('@/http/api/glossary', () => ({
  checkSykEntryBeforeSave: vi.fn(() => Promise.resolve({ data: [] }))
}))

// Mock localStorage
const mockLocalStorage = {
  getItem: vi.fn(),
  setItem: vi.fn()
}
global.localStorage = mockLocalStorage
```

### 5. 测试覆盖率目标

- **核心工具函数**：≥ 90%
- **一般工具函数**：≥ 80%
- **整体项目**：≥ 70%

### 6. 持续集成（CI）

在 CI/CD 流程中添加测试：

```yaml
# .github/workflows/test.yml
name: Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - uses: actions/setup-node@v2
      - run: npm install
      - run: npm test
      - run: npm run test:coverage
```

## 常见问题

### Q1: 测试运行失败，提示找不到模块

**解决方案**：
1. 检查 `vitest.config.js` 中的路径别名配置
2. 确保 `@` 别名指向正确的 `src` 目录

### Q2: Vue 组件测试报错

**解决方案**：
1. 确保安装了 `@vue/test-utils`
2. 在 `vitest.config.js` 中添加 `vue()` 插件

### Q3: DOM 相关测试失败

**解决方案**：
1. 确保设置了 `environment: 'jsdom'`
2. 安装了 `jsdom` 依赖

### Q4: 覆盖率报告不准确

**解决方案**：
1. 检查 `coverage.exclude` 配置
2. 确保测试文件命名符合 `*.test.js` 或 `*.spec.js`
